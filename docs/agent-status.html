The rest of the agent, at its desk

What the synth-desk branch adds to Workwith, and why an agent with a persistent identity needs it.

Branch synth-desk Try it: workwith2.synth.softmax-agents.com About 150 lines, in 5 files. It is off unless an agent turns it on.

The problem

Codinger, and Workwith after it, was built for one person on a laptop who starts short-lived Claude sessions. Each session is the only thing at work in its folder, as far as it knows.

Synth is different. Many parts of one agent run at the same time, in the same checkout:

  • about a dozen routines on systemd timers, some of which commit and push main every 30 minutes;
  • a Slack listener that answers DMs;
  • sessions on other desks (the main Workwith and this trial one).

A session at the desk could not see any of these parts. It could commit while a routine was halfway through a rebase. It could restart a service that the listener depends on. It could also miss a failed unit that was right in front of it. Its only defence was a line in AGENTS.md that said "check pgrep first", and sessions forgot it.

The change: one generic hook

Workwith does not know anything about Synth's routines, and it should not. Instead, the agent names a command, and Workwith runs it and shows its output:

CODINGER_AGENT_STATUS='python3 /var/lib/cubid/scripts/desk_status.py'
The agent's commandThe agent's own script. It knows its own routines, listeners and desks.
→
Workwith, every 15 sserver/agentstatus.ts runs it and keeps the last good answer.
→
Two placesEach message to Claude carries the text. The sidebar panel shows the summary.

What the command prints

The command prints JSON. Only text is required, and plain text also works: all of it goes to Claude, and its first line becomes the summary.

{
  "text":     "Routines running now: none.\n…",   // goes to Claude with every message
  "summary":  "Next: hourly-data-refresh 12:17 PM", // one line in the sidebar
  "busy":     false,                             // true: the dot pulses amber
  "warn":     "Failed: synth-meetings-scan.service",
  "sections": [{ "title": "Routines", "rows": [["pick-up-work", "last 12:12 · next 12:42"]] }]
}

What Claude sees

Each message gets a hidden block, next to the "task ended" notes that Workwith already sends. Sessions see it, and the lead sees it below its board:

[Desk status, 4s old]
Routines running now: none.
Starting in the next 15 min: hourly-data-refresh at 12:17 PM, github-app-token at 12:30 PM.
Failed units: synth-meetings-scan.service.
/var/lib/cubid on main: 0 ahead, 0 behind upstream, 4 modified tracked files. Last commit: …
Slack listener: up.
Sessions at my other desks: "repo-privacy" (asking, workwith), …

A short section of the system prompt (only when the hook is set) says what the block is: the server writes it, not the user. It also says to read the block before committing, pushing or restarting anything, and not to repeat it back.

Files

FileWhat it does
server/agentstatus.tsNew. Runs the command (10 s timeout, 1 MB cap), parses its output, holds the latest answer, and builds the hidden block and the prompt section.
server/index.tsAdds the block in hiddenFor() and the prompt section to the worker prompt. Adds GET /api/agent-status.
web/src/components/StatusPanel.tsxNew. The sidebar panel, which polls every 20 s.
web/src/components/Sidebar.tsx, styles.cssPuts the panel under the agent's name, and styles it. The pulse stops when the system asks for reduced motion.

Synth's side lives in its own repo: scripts/desk_status.py (the command, about 0.1 s per run, read-only) and scripts/workwith2.sh (runs this branch on port 4548).

Choices

  • It is a command, not a plugin API. Any agent can write one in any language. Workwith does not need to know about systemd, git or Slack.
  • It is off by default. When the variable is not set, there is no panel, no block and no prompt text. Laptop users see no change.
  • It fails soft. When the command errors or hangs, Workwith keeps the last good answer and shows its age ("4s old"), so a stale snapshot is easy to see.
  • The probe runs in the background. A message never waits for the command.
  • It sends a fresh snapshot with every message, not a diff. This costs about 100 tokens per message. A diff would be smaller, but Claude would have to track state across turns.

History

October: the first version was a full fork of Codiner (desk/ in agent-synth). It had its own tailnet listener and guardian check, because the agent could not edit Caddy then. Workwith has since gained agent names, avatars, guardian sign-in and signed messages, so most of that fork is no longer needed. This branch keeps only what Workwith still lacks.

Open questions

  • Should this go upstream to Workwith main? It is generic. The name CODINGER_AGENT_STATUS and the JSON shape are the parts to agree on first.
  • agents-toolkit could render the variable from agent.toml (for example [workwith] status = "scripts/desk_status.py"). Then the main desk would get it with no separate trial desk.
  • Should sessions be able to ask for a fresh status as a tool, in addition to receiving it with each message?
